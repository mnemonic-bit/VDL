# Add a refresh link to the version-mismatch warning

**Source:** User-requested feature
**Status:** Implemented
**Last refined:** 2026-09-27

## Decision summary

When the footer detects that the loaded UI version differs from the version
reported by the API, show a `Refresh page` link on its own line beneath the
version-mismatch message. Activating the link navigates to the application's
index route in the same browser tab, causing the browser to obtain the current
server-rendered HTML and its versioned static-asset URLs.

Use a real anchor whose `href` is generated with Flask's `url_for('index')`.
The refresh therefore remains a normal browser navigation and does not require
an inline handler or a new JavaScript event listener. Keep the choice with the
user: detecting a mismatch must not automatically reload the page because a
reload could discard in-progress form edits or interrupt other interaction.

## Relationship to runtime version detection

The runtime-version feature already:

- embeds the UI version in the server-rendered document;
- reads the API version from the existing `/api/health` request;
- shows a mismatch warning when the values differ or the API returns no usable
  version; and
- serves the index response with `Cache-Control: no-store` while adding the UI
  version to the JavaScript and CSS URLs.

This feature changes only the warning's presentation and action. It does not
change version comparison, health polling, cache policy, or the health API.
After navigation, the no-store index response supplies the running server's UI
version and the updated asset query strings. The next health response should
then clear the warning when the deployment is internally consistent.

An open document cannot receive new markup merely because its backend was
replaced. Consequently, a page loaded from a release that predates this
feature will continue to show the old text-only warning and must be refreshed
manually once. Pages loaded from this feature's release onward will have the
link available for later version mismatches.

## Confirmed requirements

- Show a visible `Refresh page` link whenever the existing version-mismatch
  warning is visible.
- Place the link on a separate line immediately beneath the mismatch message,
  not inline with the UI version, API version, or uptime.
- Render the control as an `<a>` element with an `href` generated by
  `url_for('index')`; do not use `href="#"` or depend on JavaScript to perform
  the navigation.
- Navigate in the current browsing context. Do not open another tab or window.
- Hide the link whenever the warning is hidden, including when UI and API
  versions match and when the API is unavailable.
- Continue showing the warning and link when a successful health response has
  a missing, empty, or malformed version, because the existing behavior treats
  `API unknown` as a mismatch.
- Preserve the existing accessible live-region explanation. When a mismatch is
  announced, tell the user that the `Refresh page` link can load the current UI.
- Keep the link keyboard-focusable, visibly underlined, and equipped with a
  clear focus indicator supplied by the browser or project styles.
- Use existing theme custom properties and `currentColor`; do not introduce a
  hard-coded light- or dark-theme color.
- Preserve the footer's centered layout and allow the message and link to wrap
  without horizontal scrolling on narrow screens.
- Do not automatically activate the link, reload after a delay, add another
  health request, write browser storage, or add a frontend dependency.

## Presentation

The mismatch state should read conceptually as:

```text
UI v0.8.6 · API v0.9.0 · Uptime 2 Minutes
version mismatch
Refresh page
```

The exact versions and uptime remain dynamic. The warning container owns both
the message and link so the existing `hidden` state can reveal and conceal them
together. Its layout should occupy a full footer row and stack the two items
vertically. Styling that gives the container an explicit display value must
also preserve the `hidden` attribute, for example with a targeted
`.version-warning[hidden]` rule.

The link should inherit the footer's mismatch color. Underlining and native
anchor semantics distinguish it as an action without introducing another
button style.

## Implementation outline

- In `templates/index.html`, replace the text-only `versionWarning` span with a
  warning container holding the mismatch text and a `Refresh page` anchor.
- Generate the anchor destination with `url_for('index')` so routing remains
  authoritative and the control works without JavaScript event handling.
- In `static/styles.css`, make the visible warning consume a full footer row
  and stack its message and link while explicitly retaining hidden-state
  behavior.
- In `static/app.js`, retain `warning.hidden = !mismatched`. Update the
  accessible status text to refer to the link rather than giving only a plain
  refresh instruction.
- Extend `tests/browser/version-status.spec.cjs` to cover link visibility,
  destination, keyboard-accessible anchor semantics, and navigation from a
  mismatched page to current UI markup.
- Increment `VERSION` once as a feature when implementing the shipped UI
  change. Creating this specification alone is documentation-only and does not
  change `VERSION`.

## Acceptance criteria

- With matching UI and API versions, neither the mismatch message nor the
  refresh link is visible.
- With different non-empty versions, the footer shows `version mismatch` and a
  visible `Refresh page` link immediately below it.
- With `API unknown`, the mismatch message and link are visible; with
  `API unavailable`, both are hidden.
- The link's resolved URL points to the Flask index route on the current origin
  and has no `target` that opens a separate browsing context.
- Activating the link issues a normal index navigation. The response is not
  satisfied by stale HTML, and the newly rendered document reports the current
  server UI version.
- Once the refreshed page receives a matching health response, the mismatch
  message and refresh link disappear.
- The link remains usable with JavaScript event handlers disabled after the
  mismatch state has already been rendered.
- A keyboard user can focus and activate the link, and its purpose is clear
  from the link text without surrounding visual context.
- The warning occupies its own centered footer row and remains legible without
  horizontal scrolling at the narrowest browser viewport covered by the UI
  tests.
- Existing version, uptime, health-check, server-unavailable, light-theme, and
  dark-theme behavior remains unchanged.

## Verification

Add focused browser coverage to the existing version-status suite, then run
the complete automated test suite:

```bash
python -m unittest discover -s tests -v
```

Manually leave a page open, restart the server with a different `VERSION`, and
wait for the next existing health check. Confirm that the mismatch message and
link appear, that clicking the link replaces the page in the same tab, and
that a consistent deployment clears the warning after the refreshed page
checks health.
